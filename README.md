# Exam Schedule CSP

## 1 ما هو المشروع

نظام جدولة امتحانات عبر الويب. المستخدم يرفع ملف Excel بعمودي `Student` و`Subject`. الخادم يبني خريطة طالب إلى مواد، ثم يختار خوارزمية حسب عدد الطلاب والمواد، ويكتب جدولاً بأيام الأحد إلى الخميس وأربع فترات زمنية، ثم يعرض النتيجة ويتيح تنزيل Excel.

الصياغة في `solver/scheduler.py`: Constraint Satisfaction Problem باستخدام OR-Tools CP-SAT، مع مسارات تقريبية عندما يكبر الحجم أو يفشل الحل.

وصف README السابق عن جدولة محلية بلا اتصالات خارجية أثناء الحل يطابق الكود: لا طلبات HTTP صادرة داخل `solver` أو `app.py`.

## 2 لمن هذا المشروع

مستخدم واحد يفتح المتصفح على الجهاز نفسه. لا حسابات ولا أدوار. مناسب لمن يعد جدول اختبارات من كشف تسجيل طلاب ومواد.

## 3 الميزات الفعلية

| الميزة | التفصيل |
| --- | --- |
| رفع xlsx أو xls | `POST /upload` |
| حد الحجم | 10 ميغابايت من `MAX_CONTENT_LENGTH` |
| معالجة في خيط خلفي | `threading.Thread` داخل `process_schedule_background` |
| صفحة تقدم | `GET /processing` و`GET /messages` |
| عرض النتائج | `GET /results` |
| تنزيل الملف الناتج | `GET /download` |
| التحقق من الأعمدة | `Student` و`Subject` إلزاميان |
| تنظيف | حذف الصفوف الفارغة والتكرار |
| اختيار الخوارزمية | حسب الحدود في `solve_schedule` |
| واجهة | قوالب `index.html` و`processing.html` و`result.html` و`base.html` |

حدود الاختيار في `solve_schedule`:

| الشرط | الدالة |
| --- | --- |
| طلاب أكثر من 500 أو مواد أكثر من 100 | `solve_advanced_csp_schedule` |
| طلاب أكثر من 200 أو مواد أكثر من 50 | `solve_optimized_csp_schedule` |
| طلاب 50 أو أقل ومواد 50 أو أقل | `solve_direct_heuristic` |
| غير ذلك | `solve_enhanced_csp_schedule` |

أيام الفترات المشتركة في أكثر من دالة حل: الأحد، الاثنين، الثلاثاء، الأربعاء، الخميس. الفترات: `08:00-10:00` و`10:00-12:00` و`12:00-14:00` و`14:00-16:00`.

قيد «كل مادة في خانة واحدة» يظهر في نماذج CP-SAT عبر مجموع المتغيرات يساوي 1. قيد «حد أقصى امتحانين في اليوم» يظهر في مسار `solve_regular_schedule` عند السطر الذي يضيف `<= 2`. هذا القيد غير مكرر حرفياً في كل دوال الحل الأخرى داخل الملف.

صفوف الإدخال:

| Student | Subject |
| --- | --- |

المخرجات التي يبنيها المسار البسيط قاموس لكل مادة: `Subject`, `DayIndex`, `DayName`, `PeriodIndex`, `TimeRange`. الملف يُحفظ باسم يبدأ بـ `exam_schedule_simple_` ثم طابع وقت `YYYYMMDD_HHMMSS` وامتداد `xlsx` تحت `static/downloads` بالنسبة لمجلد المشروع (من حساب المسار داخل `scheduler.py`).

ملفات أسماء أخرى قد تُنتجها دوال حل مختلفة داخل نفس الملف. النمط المشترك كتابة DataFrame إلى Excel في مجلد التنزيلات.

## 5 رحلة الاستخدام

1. تشغيل `python app.py`.
2. فتح `http://127.0.0.1:5000`.
3. اختيار ملف Excel.
4. التحقق من الامتداد والحجم والأعمدة.
5. حفظ باسم فريد `uuid_اسم` ثم خيط معالجة.
6. الصفحة `/processing` تعرض الرسائل حتى تكتمل أو تفشل.
7. عند النجاح الانتقال إلى `/results` ثم تنزيل من `/download`.
8. ملف الرفع المؤقت يُحذف بعد انتهاء المعالجة في مسار النجاح ومسارات الخطأ الظاهرة في `process_schedule_background`.

الحالة العامة في الذاكرة: `idle` ثم `processing` ثم `completed` أو `error`. المتغيرات عامة على العملية: `schedule_results` و`output_file_path` و`processing_messages`.

## 17 الخادم الخلفي

Flask مع مفتاح جلسة سلسلة ثابتة في `app.py` لاستخدام رسائل `flash`. لا تُنسخ هنا. المعالجة خارج طلب الرفع حتى لا يبقى المتصفح معلقاً على الحل. الرسائل تُجمع في قائمة ويقرأها `GET /messages`.

## 18 تدفق الطلب

```
POST /upload
  -> التحقق من الملف والامتداد والحجم
  -> secure_filename + uuid
  -> validate_input_file
  -> خيط process_schedule_background
  -> إعادة توجيه /processing

GET /processing
  -> إن اكتملت: إعادة توجيه /results
  -> إن فشلت: عرض الخطأ والرسائل
  -> وإلا: صفحة الانتظار

GET /download
  -> يرفض إن الحالة ليست completed
  -> يرفض ملفاً غير xlsx أو xls أو ملفاً فارغاً
  -> send_file كمرفق
```

## 29 دليل التطوير

- غيّر الأيام أو الفترات في القوائم داخل دوال الحل. القوائم مكررة في أكثر من دالة في `scheduler.py`.
- إضافة قيد طالب (مثل حد يومي) يلزم النموذج الذي يُستدعى فعلياً حسب حجم البيانات.
- `solve_regular_schedule` يحتوي قيد `<= 2` لعدد الفترات المستخدمة في اليوم ضمن ذلك المسار.
- حالة المعالجة ليست لكل مستخدم. تشغيلان متوازيان يتشاركان نفس المتغيرات العامة.
